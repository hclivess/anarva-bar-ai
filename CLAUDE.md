# Working rules for Anarvā

These are the owner's standing rules. They apply to every change, every claim and every comment.

## 1. Every strategic claim is verified against replays

- **Always verify claims against replays.** Before arguing that strong players do X, or that X wins,
  find it in replays and measure it. Intuition, forum lore and "humans usually..." are hypotheses until
  a replay shows them.
- **Reference the replay.** Whenever a strategy is defended (in code comments, docs, issues, commit
  messages or chat), cite the replay(s) it rests on: file name (or replay id), map, format, players and
  the minute where it happens, or the aggregate from `tools/analyze_*.py` with the set it ran on.
  No reference, no claim.
- **Keep the library broad and categorised.** Download top-player replays across configurations:
  1v1, 2v2, 3v3, 4v4, 8v8, FFA, and humans vs bots (1vN). Categorise each by the type of gameplay it
  shows (see [REPLAYS.md](REPLAYS.md)): format, map type, outcome and length, and play style
  (eco boom, early aggression, turtle/porc, air, T2 rush, commander play, sea, and so on).
  A finding from one category does not carry over to another unless the replays show it.
  Example: commanders stand 2000-3000 out all game in team games, but not in 1v1.
- Tools: `tools/fetch_replays.py` (download by preset and skill), `tools/run_replay.py` (play back
  headless with the analyzer widget), `tools/analyze_replays.py` (economy curves) and
  `tools/analyze_comm.py` (commander behaviour). Extend the analyzer widget
  (`tools/replay_harness/LuaUI/Widgets/zz_replay_analyzer.lua`) when a claim needs data it doesn't log yet.

## 2. No static thresholds: active decisions only

A decision is a live comparison of value (metal-equivalent over the planning horizon, minus risk), never
a hand-picked cutoff. A threshold is a frozen priority. Copy the reasoning behind a behaviour seen in
replays, never the behaviour itself.

## 3. Everything is measured

- Every behaviour sits behind a flag (script `F_*` in `brain.as`, core switches in
  `util/AnarvaSwitches.h`), ships **off**, and is turned on only after it wins a paired A/B test:
  2 concurrent rounds x 8 games vs 2 BARb hard (judged on outright losses, value share, damage ratio).
  Both rounds must agree; the noise floor is about +-0.15 share per 8 games.
- Results go into `progress.json`; `FEATURES.md` is regenerated by `tools/gen_features.py`.
- The 1v1 release gate: a pre-alpha is tagged only when the current defaults clearly beat one BARb hard.
